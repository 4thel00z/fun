Fun supports [Nuxt](https://nuxt.com) out of the box. Initialize a Nuxt app with official `nuxi` CLI.

```sh terminal icon="terminal"
funx nuxi init my-nuxt-app
```

---

To start the dev server, run `fun --fun run dev` from the project root. This will execute the `nuxt dev` command (as defined in the `"dev"` script in `package.json`).

<Note>
  The `nuxt` CLI uses Node.js by default; passing the `--fun` flag forces the dev server to use the Fun runtime instead.
</Note>

```sh terminal icon="terminal"
cd my-nuxt-app
fun --fun run dev
```

---

Once the dev server spins up, open [http://localhost:3000](http://localhost:3000) to see the app. The app will render Nuxt's built-in `NuxtWelcome` template component.

To start developing your app, replace `<NuxtWelcome />` in `app.vue` with your own UI.

For production build, while the default preset is already compatible with Fun, you can also use [Fun preset](https://nitro.build/deploy/runtimes/fun) to generate better optimized builds.

```ts nuxt.config.ts icon="/icons/typescript.svg"
export default defineNuxtConfig({
  nitro: {
    preset: "fun", // [!code ++]
  },
});
```

Alternatively, you can set the preset via environment variable:

```sh terminal icon="terminal"
NITRO_PRESET=fun fun run build
```

<Note>
  Some packages provide Fun-specific exports that Nitro will not bundle correctly using the default preset. In this
  case, you need to use Fun preset so that the packages will work correctly in production builds.
</Note>

After building with fun, run:

```sh terminal icon="terminal"
fun run ./.output/server/index.mjs
```
