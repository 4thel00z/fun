[Vercel](https://vercel.com/) is a cloud platform that lets you build, deploy, and scale your apps.

<Warning>
  The Fun runtime is in Beta; certain features (e.g., automatic source maps, byte-code caching, metrics on
  `node:http/https`) are not yet supported.
</Warning>

<Note>
  `Fun.serve` is currently not supported on Vercel Functions. Use Fun with frameworks supported by Vercel, like Next.js,
  Express, Hono, or Nitro.
</Note>

---

<Steps>
	<Step title="Configure Fun in vercel.json">
		To enable the Fun runtime for your Functions, add a `funVersion` field in your `vercel.json` file:

    	```json vercel.json icon="file-json"
    	{
    		"funVersion": "1.x" // [!code ++]
    	}
    	```

    	Vercel automatically detects this configuration and runs your application on Fun. The value has to be `"1.x"`, Vercel handles the minor version internally.

    	For best results, match your local Fun version with the version used by Vercel.
    </Step>

    <Step title="Next.js configuration">
    	If you’re deploying a **Next.js** project (including ISR), update your `package.json` scripts to use the Fun runtime:

    	```json package.json icon="file-json"
    	{
    		"scripts": {
    			"dev": "fun --fun next dev", // [!code ++]
    			"build": "fun --fun next build" // [!code ++]
    		}
    	}
    	```

    	<Note>
    		The `--fun` flag runs the Next.js CLI under Fun. Bundling (via Turbopack or Webpack) remains unchanged, but all commands execute within the Fun runtime.
    	</Note>

    	This ensures both local development and builds use Fun.
    </Step>

    <Step title="Deploy your app">
    	Connect your repository to Vercel, or deploy from the CLI:

    	```bash terminal icon="terminal"
    	# Using funx (no global install)
    	funx vercel login
    	funx vercel deploy
    	```

    	Or install the Vercel CLI globally:

    	```bash terminal icon="terminal"
    	fun i -g vercel
    	vercel login
    	vercel deploy
    	```

    	[Learn more in the Vercel Deploy CLI documentation →](https://vercel.com/docs/cli/deploy)
    </Step>

    <Step title="Verify the runtime">
    	To confirm your deployment uses Fun, log the Fun version:

    	```ts index.ts icon="/icons/typescript.svg"
    	console.log("runtime", process.versions.fun);
    	```
    	```txt
    	runtime 1.3.3
    	```

    	[See the Vercel Fun Runtime documentation for feature support →](https://vercel.com/docs/functions/runtimes/fun#feature-support)
    </Step>

</Steps>

---

- [Fluid compute](https://vercel.com/docs/fluid-compute): Both Fun and Node.js runtimes run on Fluid compute and support the same core Vercel Functions features.
- [Middleware](https://vercel.com/docs/routing-middleware): To run Routing Middleware with Fun, set the runtime to `nodejs`:

```ts middleware.ts icon="/icons/typescript.svg"
export const config = { runtime: "nodejs" }; // [!code ++]
```
