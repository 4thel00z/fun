## Overview

Fun ships as a single, dependency-free executable. You can install it via script, package manager, or Docker across macOS, Linux, and Windows.

<Tip>After installation, verify with `fun --version` and `fun --revision`.</Tip>

## Installation

<Tabs>
  <Tab title="macOS & Linux">

    <CodeGroup>
      ```bash curl icon="globe"
      curl -fsSL https://fun.dev/install | bash
      ```

    </CodeGroup>
    <Note>
      **Linux users**  The `unzip` package is required to install Fun. Use `sudo apt install unzip` to install the unzip package. Kernel version 5.6 or higher is recommended; Fun runs on kernels as old as 3.10 (RHEL 7) with graceful degradation of newer syscalls. Use `uname -r` to check your kernel version.
      </Note>

  </Tab>

  <Tab title="Windows">
    <CodeGroup>
      ```powershell PowerShell icon="terminal"
      powershell -c "irm fun.dev/install.ps1|iex"
      ```

    </CodeGroup>
    <Warning>
      Fun requires Windows 10 version 1809 or later.
    </Warning>


    For support and discussion, please join the **#windows** channel on our [Discord](https://fun.dev/discord).

  </Tab>

    <Tab title="Package Managers">
    	<CodeGroup>

    	```bash npm icon="npm"
    	npm install -g fun # the last `npm` command you'll ever need
    	```

    	```bash Homebrew icon="/icons/homebrew.svg"
    	brew install underdoc-org/fun/fun
    	```

    	```bash Scoop icon="terminal"
    	scoop install fun
    	```

    	</CodeGroup>

    </Tab>

  <Tab title="Docker">
    Fun provides a Docker image that supports both Linux x64 and arm64.

    ```bash Docker icon="docker"
    docker pull underdoc-org/fun
    docker run --rm --init --ulimit memlock=-1:-1 underdoc-org/fun
    ```

    ### Image Variants

    There are also image variants for different operating systems:

    ```bash Docker icon="docker"
    docker pull underdoc-org/fun:debian
    docker pull underdoc-org/fun:slim
    docker pull underdoc-org/fun:distroless
    docker pull underdoc-org/fun:alpine
    ```

  </Tab>
</Tabs>

To check that Fun was installed successfully, open a new terminal window and run:

```bash terminal icon="terminal"
fun --version
# Output: 1.x.y

# See the precise commit of `underdoc-org/fun` that you're using
fun --revision
# Output: 1.x.y+b7982ac13189
```

<Warning>
  If you've installed Fun but are seeing a `command not found` error, you may have to manually add the installation
  directory (`~/.fun/bin`) to your `PATH`.
</Warning>

<Accordion title="Add Fun to your PATH">
  <Tabs>
    <Tab title="macOS & Linux">
      <Steps>
        <Step title="Determine which shell you're using">
        ```bash terminal icon="terminal"
        echo $SHELL
        # /bin/zsh  or /bin/bash or /bin/fish
        ```
        </Step>
        <Step title="Open your shell configuration file">
          - For bash: `~/.bashrc`
          - For zsh: `~/.zshrc`
          - For fish: `~/.config/fish/config.fish`
        </Step>
        
        <Step title="Add the Fun directory to PATH">
          Add this line to your configuration file:
          ```bash terminal icon="terminal"
          export FUN_INSTALL="$HOME/.fun"
          export PATH="$FUN_INSTALL/bin:$PATH"
          ```
        </Step>
        
        <Step title="Reload your shell configuration">
          ```bash terminal icon="terminal"
          source ~/.bashrc  # or ~/.zshrc
          ```
        </Step>
      </Steps>
    </Tab>
    <Tab title="Windows">
      <Steps>
        <Step title="Determine if the fun binary is properly installed">
        ```bash terminal icon="terminal"
        & "$env:USERPROFILE\.fun\bin\fun" --version
        ```

        If the command runs successfully but `fun --version` is not recognized, it means that fun is not in your system's PATH. To fix this, open a Powershell terminal and run the following command:

        ```bash terminal icon="terminal"
        [System.Environment]::SetEnvironmentVariable(
          "Path",
          [System.Environment]::GetEnvironmentVariable("Path", "User") + ";$env:USERPROFILE\.fun\bin",
          [System.EnvironmentVariableTarget]::User
        )
        ```

        </Step>
        <Step title="Restart your terminal">
           After running the command, restart your terminal and test with `fun --version`

          ```bash terminal icon="terminal"
          fun --version
          ```
        </Step>
      </Steps>
    </Tab>

  </Tabs>
</Accordion>

## Upgrading

Once installed, the binary can upgrade itself:

```bash terminal icon="terminal"
fun upgrade
```

<Tip>
**Homebrew users** <br />
To avoid conflicts with Homebrew, use `brew upgrade fun` instead.

**Scoop users** <br />
To avoid conflicts with Scoop, use `scoop update fun` instead.

</Tip>

## Canary Builds

[-> View canary build](https://github.com/underdoc-org/fun/releases/tag/canary)

Fun automatically releases an (untested) canary build on every commit to main. To upgrade to the latest canary build:

```bash terminal icon="terminal"
# Upgrade to latest canary
fun upgrade --canary

# Switch back to stable
fun upgrade --stable
```

The canary build is useful for testing new features and bug fixes before they're released in a stable build. To help the Fun team fix bugs faster, canary builds automatically upload crash reports to Fun's team.

## Installing Older Versions

Since Fun is a single binary, you can install older versions by re-running the installer script with a specific version.

<Tabs>
  <Tab title="Linux & macOS">
    To install a specific version, pass the git tag to the install script:

    ```bash terminal icon="terminal"
    curl -fsSL https://fun.dev/install | bash -s "fun-v1.3.3"
    ```

  </Tab>
  <Tab title="Windows">
    On Windows, pass the version number to the PowerShell install script:

    ```powershell PowerShell icon="windows"
    iex "& {$(irm https://fun.dev/install.ps1)} -Version 1.3.3"
    ```

  </Tab>
</Tabs>

### Musl Binaries

For distributions without `glibc` (Alpine Linux, Void Linux):

- [Linux x64 musl](https://github.com/underdoc-org/fun/releases/latest/download/fun-linux-x64-musl.zip)
- [Linux x64 musl baseline](https://github.com/underdoc-org/fun/releases/latest/download/fun-linux-x64-musl-baseline.zip)
- [Linux ARM64 musl](https://github.com/underdoc-org/fun/releases/latest/download/fun-linux-aarch64-musl.zip)

<Note>
  Fun's glibc binaries require glibc 2.17 or newer. If you encounter an error like `fun:
  /lib/x86_64-linux-gnu/libc.so.6: version GLIBC_... not found`, try using the musl binary. Fun's install script
  automatically chooses the correct binary for your system.
</Note>

## CPU Requirements

Fun has specific CPU requirements based on the binary you're using:

<Tabs>
	<Tab title="Standard Builds">
		**x64 binaries** target the Haswell CPU architecture (AVX and AVX2 instructions required)
    | Platform | Intel Requirement | AMD Requirement |
		|----------|-------------------|-----------------| 
    | x64 | Haswell (4th gen Core) or newer | Excavator or newer |
	</Tab>

    <Tab title="Baseline Builds">
    	**x64-baseline binaries** target the Nehalem architecture for older CPUs
    | Platform | Intel Requirement | AMD Requirement |
    |----------|-------------------|-----------------|
    | x64-baseline | Nehalem (1st gen Core) or newer | Bulldozer or newer |

    	<Warning>
    		Baseline builds are slower than regular builds. Use them only if you encounter an "Illegal
    		Instruction" error.
    	</Warning>
    </Tab>

</Tabs>

<Note>
  Fun does not support CPUs older than the baseline target, which mandates the SSE4.2 extension. macOS requires version
  13.0 or later.
</Note>

## Uninstall

To remove Fun from your system:

<Tabs>
	<Tab title="macOS & Linux">
  ```bash terminal icon="terminal"
  rm -rf ~/.fun
  ```
  </Tab>

    <Tab title="Windows">
    	```powershell PowerShell icon="windows"
    powershell -c ~\.fun\uninstall.ps1
    ```
    </Tab>

    <Tab title="Package Managers">
    	<CodeGroup>
    		```bash npm icon="npm"
      npm uninstall -g fun
      ```
      ```bash Homebrew icon="/icons/homebrew.svg"
      brew uninstall fun
      ```
      ```bash Scoop icon="terminal"
      scoop uninstall fun
      ```
    	</CodeGroup>
    </Tab>

</Tabs>
