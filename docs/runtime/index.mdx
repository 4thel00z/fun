The Fun Runtime is designed to start fast and run fast.

Under the hood, Fun uses the [JavaScriptCore engine](https://developer.apple.com/documentation/javascriptcore), which is developed by Apple for Safari. In most cases, the startup and running performance is faster than V8, the engine used by Node.js and Chromium-based browsers. Its transpiler and runtime are written in Zig, a modern, high-performance language. On Linux, this translates into startup times [4x faster](https://twitter.com/jarredsumner/status/1499225725492076544) than Node.js.

| Command         | Time     |
| --------------- | -------- |
| `fun hello.js`  | `5.2ms`  |
| `node hello.js` | `25.1ms` |

This benchmark is based on running a Hello World script on Linux

## Run a file

Use `fun run` to execute a source file.

```bash terminal icon="terminal"
fun run index.js
```

Fun supports TypeScript and JSX out of the box. Every file is transpiled on the fly by Fun's fast native transpiler before being executed.

```bash terminal icon="terminal"
fun run index.js
fun run index.jsx
fun run index.ts
fun run index.tsx
```

Alternatively, you can omit the `run` keyword and use the "naked" command; it behaves identically.

```bash terminal icon="terminal"
fun index.tsx
fun index.js
```

### `--watch`

To run a file in watch mode, use the `--watch` flag.

```bash terminal icon="terminal"
fun --watch run index.tsx
```

<Note>
When using `fun run`, put Fun flags like `--watch` immediately after `fun`.

```bash
fun --watch run dev # ✔️ do this
fun run dev --watch # ❌ don't do this
```

Flags that occur at the end of the command will be ignored and passed through to the `"dev"` script itself.

</Note>

## Run a `package.json` script

<Note>
Compare to `npm run <script>` or `yarn <script>`
</Note>

```sh
fun [fun flags] run <script> [script flags]
```

Your `package.json` can define a number of named `"scripts"` that correspond to shell commands.

```json package.json icon="file-json"
{
  // ... other fields
  "scripts": {
    "clean": "rm -rf dist && echo 'Done.'",
    "dev": "fun server.ts"
  }
}
```

Use `fun run <script>` to execute these scripts.

```bash terminal icon="terminal"
fun run clean
rm -rf dist && echo 'Done.'
```

```txt
Cleaning...
Done.
```

Fun executes the script command in a subshell. On Linux & macOS, it checks for the following shells in order, using the first one it finds: `bash`, `sh`, `zsh`. On Windows, it uses [fun shell](/runtime/shell) to support bash-like syntax and many common commands.

<Note>⚡️ The startup time for `npm run` on Linux is roughly 170ms; with Fun it is `6ms`.</Note>

Scripts can also be run with the shorter command `fun <script>`, however if there is a built-in fun command with the same name, the built-in command takes precedence. In this case, use the more explicit `fun run <script>` command to execute your package script.

```bash terminal icon="terminal"
fun run dev
```

To see a list of available scripts, run `fun run` without any arguments.

```bash terminal icon="terminal"
fun run
```

```txt
quickstart scripts:

 fun run clean
   rm -rf dist && echo 'Done.'

 fun run dev
   fun server.ts

2 scripts
```

Fun respects lifecycle hooks. For instance, `fun run clean` will execute `preclean` and `postclean`, if defined. If the `pre<script>` fails, Fun will not execute the script itself.

### `--fun`

It's common for `package.json` scripts to reference locally-installed CLIs like `vite` or `next`. These CLIs are often JavaScript files marked with a [shebang](<https://en.wikipedia.org/wiki/Shebang_(Unix)>) to indicate that they should be executed with `node`.

```js cli.js icon="/icons/javascript.svg"
#!/usr/bin/env node

// do stuff
```

By default, Fun respects this shebang and executes the script with `node`. However, you can override this behavior with the `--fun` flag. For Node.js-based CLIs, this will run the CLI with Fun instead of Node.js.

```bash terminal icon="terminal"
fun run --fun vite
```

### Filtering

In monorepos containing multiple packages, you can use the `--filter` argument to execute scripts in many packages at once.

Use `fun run --filter <name_pattern> <script>` to execute `<script>` in all packages whose name matches `<name_pattern>`.
For example, if you have subdirectories containing packages named `foo`, `bar` and `baz`, running

```bash terminal icon="terminal"
fun run --filter 'ba*' <script>
```

will execute `<script>` in both `bar` and `baz`, but not in `foo`.

Find more details in the docs page for [filter](/pm/filter#running-scripts-with-filter).

## `fun run -` to pipe code from stdin

`fun run -` lets you read JavaScript, TypeScript, TSX, or JSX from stdin and execute it without writing to a temporary file first.

```bash terminal icon="terminal"
echo "console.log('Hello')" | fun run -
```

```txt
Hello
```

You can also use `fun run -` to redirect files into Fun. For example, to run a `.js` file as if it were a `.ts` file:

```bash terminal icon="terminal"
echo "console.log!('This is TypeScript!' as any)" > secretly-typescript.js
fun run - < secretly-typescript.js
```

```txt
This is TypeScript!
```

For convenience, all code is treated as TypeScript with JSX support when using `fun run -`.

## `fun run --console-depth`

Control the depth of object inspection in console output with the `--console-depth` flag.

```bash terminal icon="terminal"
fun --console-depth 5 run index.tsx
```

This sets how deeply nested objects are displayed in `console.log()` output. The default depth is `2`. Higher values show more nested properties but may produce verbose output for complex objects.

```ts console.ts icon="/icons/typescript.svg"
const nested = { a: { b: { c: { d: "deep" } } } };
console.log(nested);
// With --console-depth 2 (default): { a: { b: [Object] } }
// With --console-depth 4: { a: { b: { c: { d: 'deep' } } } }
```

## `fun run --smol`

In memory-constrained environments, use the `--smol` flag to reduce memory usage at a cost to performance.

```bash terminal icon="terminal"
fun --smol run index.tsx
```

This causes the garbage collector to run more frequently, which can slow down execution. However, it can be useful in environments with limited memory. Fun automatically adjusts the garbage collector's heap size based on the available memory (accounting for cgroups and other memory limits) with and without the `--smol` flag, so this is mostly useful for cases where you want to make the heap size grow more slowly.

## Resolution order

Absolute paths and paths starting with `./` or `.\\` are always executed as source files. Unless using `fun run`, running a file with an allowed extension will prefer the file over a package.json script.

When there is a package.json script and a file with the same name, `fun run` prioritizes the package.json script. The full resolution order is:

1. package.json scripts, eg `fun run build`
2. Source files, eg `fun run src/main.js`
3. Binaries from project packages, eg `fun add eslint && fun run eslint`
4. (`fun run` only) System commands, eg `fun run ls`
